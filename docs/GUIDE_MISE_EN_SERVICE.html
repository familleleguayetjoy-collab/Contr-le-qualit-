ComplyEC — mise en service, demain soir

Quarante minutes, six étapes, dans l’ordre. Chaque étape dit ce qu’on doit voir quand c’est réussi, et quoi faire si ça bloque. Les libellés des écrans Supabase et Netlify peuvent varier légèrement d’une version à l’autre : cherchez le mot le plus proche.

Ce qui est prêt et vérifié avant la séance. Les cinq scripts SQL ont été exécutés sur une base Postgres 16 neuve, puis rejoués sur une base contenant des données : aucune erreur, aucune donnée perdue. La fonction serveur a été exécutée dans ses trois modes (création, refus, réinitialisation). Le mode « données réelles » a passé sa recette à deux postes : écritures simultanées, coupure réseau, droits du collaborateur. Ce qui n’a pas pu être vérifié d’ici : le projet Supabase réel et Netlify, inaccessibles depuis l’environnement de développement. C’est l’objet de la séance.

Avant de commencer

  • L’accès au projet Supabase du cabinet (celui de supabase-config.js : tnzdopummupchhupzcso).
  • Un compte GitHub qui voit le dépôt familleleguayetjoy-collab/Contr-le-qualit-.
  • Un compte Netlify (gratuit ; « Sign up with GitHub » est le plus court).
  • Le prénom, le nom et l’e-mail du ou des collaborateurs du pilote.
  • Le tableur des clients du pilote : une ligne par client, colonnes Nom, SIREN, Forme (SARL, SAS, SCI, Particulier…), Collaborateur (prénom et nom, ou initiales).
  • Deux navigateurs, ou une fenêtre de navigation privée : un poste « expert-comptable », un poste « collaborateur ».

Les six étapes

1. Région et scripts SQL ≈ 10 min

  1. Supabase → votre projet → Project Settings → General : relevez la Region.
    Si la région n’est pas dans l’Union européenne (Paris eu-west-3, Francfort eu-central-1, Irlande eu-west-1), arrêtez là et dites-le-moi avant de saisir le moindre dossier : un projet ne change pas de région, il faut en recréer un.
  2. Menu de gauche → SQL Editor → New query.
  3. Sur GitHub, ouvrez le dossier supabase/ du dépôt. Pour chacun des cinq fichiers, dans cet ordre : ouvrir le fichier, bouton « copier » (Copy raw file), coller dans l’éditeur SQL, Run.
    OrdreFichierCe qu’il crée
    1schema.sqlcabinets, comptes, règles d’accès
    2schema_002_donnees_metier.sqltables métier
    3schema_003_lettres_et_vigilance.sqllettres, vigilance
    4schema_004_identite_documents.sqlidentité des documents
    5schema_005_etat_partage.sqldonnées partagées du cabinet, historique, droits
    Les scripts déjà passés se rejouent sans risque. Résultat attendu à chaque fois : Success. No rows returned. Des lignes « NOTICE … skipping » sont normales.
  4. Vérification, dans une nouvelle requête : 
    select column_name from information_schema.columns
 where table_name = 'cabinets' and column_name = 'donnees_reelles';
    Une ligne donnees_reelles : c’est bon.
Si ça bloque. Une erreur « relation … does not exist » : un script précédent n’est pas passé ; reprenez dans l’ordre. Une autre erreur : copiez-la telle quelle et envoyez-la-moi.

2. La fonction serveur des comptes ≈ 6 min

Elle crée le compte d’un collaborateur avec un mot de passe provisoire. Aucun e-mail n’est envoyé : sans serveur d’envoi configuré, Supabase refuse d’écrire aux adresses extérieures à l’équipe du projet. L’expert-comptable remet le mot de passe en main propre ; le collaborateur le change à sa première connexion.

  1. Supabase → Edge Functions → Deploy a new function → Via Editor.
  2. Nom de la fonction, exactement : invite-collaborateur.
  3. Effacez le code d’exemple ; collez tout le contenu de supabase/functions/invite-collaborateur/index.ts (GitHub, bouton « copier »).
  4. Deploy function.
Si ça bloque.
  • L’éditeur n’existe pas dans votre tableau de bord : la même chose se fait en ligne de commande, npx supabase login, npx supabase link --project-ref tnzdopummupchhupzcso, puis npx supabase functions deploy invite-collaborateur depuis le dossier du dépôt.
  • À l’étape 5, la création d’un compte répond « Clé serveur absente » : Supabase → Project Settings → API Keys, copiez la clé secrète (secret / service_role) ; puis Edge Functions → Secrets → ajoutez COMPLYEC_CLE_SERVEUR avec cette valeur. Elle ne quitte jamais le serveur.
  • Elle répond « Invalid JWT » (401) : dans les réglages de la fonction, désactivez « Verify JWT » ; la fonction vérifie elle-même l’identité de l’appelant.

3. Mise en ligne sur Netlify ≈ 8 min

  1. Netlify → Add new site (ou Add new project) → Import an existing project → GitHub → autorisez Netlify à lire le dépôt Contr-le-qualit-.
  2. Branche à publier : claude/comply-ec-discussion-bug-hevgkm.
  3. Réglages de construction : Build command vide, Publish directory : publication (le fichier netlify.toml du dépôt le dit déjà).
  4. Deploy. Puis Site configuration → Change site name : par exemple complyec-s2a. L’adresse devient https://complyec-s2a.netlify.app. Notez-la ici : ……………………………………………
En ouvrant l’adresse, l’écran « Vous êtes : Expert-comptable / Collaborateur » s’affiche.

Ensuite, chaque mise à jour du dépôt est republiée seule, en une minute environ. Pour revenir à une version précédente : Deploys → choisir la version → Publish deploy.

4. L’adresse de l’application dans Supabase ≈ 2 min

Supabase → Authentication → URL Configuration : Site URL = l’adresse Netlify ; dans Redirect URLs, ajoutez la même adresse. Sans cela, un lien « mot de passe oublié » renverrait vers une page qui n’existe pas.

5. Passer le cabinet en données réelles, créer le compte du pilote ≈ 7 min

  1. Sur l’adresse Netlify, connectez-vous avec votre compte expert-comptable.
  2. Paramètres → Mise en service et pilote → Passer aux données réelles… → cochez, confirmez. La page se recharge.
    En bas de la barre de gauche : « ✓ Tout est enregistré ». Les dossiers fictifs ont disparu.
  3. Paramètres → Utilisateurs et gouvernance → + Ajouter un collaborateur → prénom, nom, e-mail → Créer l’espace. Le mot de passe provisoire s’affiche une seule fois : notez-le.
  4. Dans l’autre navigateur : même adresse, « Collaborateur », e-mail et mot de passe provisoire. ComplyEC demande aussitôt de choisir un nouveau mot de passe.
Si ça bloque. Le bouton « Passer aux données réelles » n’apparaît pas et la page dit que le script 005 n’est pas exécuté : refaites l’étape 1, script 5. La création du compte échoue : le message dit pourquoi ; voir l’étape 2.

6. Les clients du pilote, et le test à deux postes ≈ 7 min

  1. Poste expert-comptable : Paramètres → Mise en service et pilote → Importer la liste des clients → choisir le tableur → vérifier la correspondance des colonnes → Valider l’import.
  2. Vérifier « Chaque dossier a son collaborateur ». Les dossiers sans collaborateur s’attribuent dans Utilisateurs et gouvernance (cliquer sur le collaborateur → Attribuer).
  3. Anomalies : chaque dossier y apparaît avec ce qui manque, daté d’aujourd’hui. C’est normal : rien n’est encore prouvé dans ComplyEC.
  4. Test à deux postes : Préparer le contrôle → Indépendance → Attestations d’indépendance → Générer les attestations (un document Word se télécharge aussi : c’est normal). Sur le poste collaborateur, dans les vingt secondes : Mes obligations → l’attestation est à signer → Signer. Sur le poste expert-comptable, la ligne passe à « signée électroniquement ».
Si l’attestation signée apparaît sur l’autre poste, la mise en service est faite.

À la fin de la séance — ou samedi matin, avant toute régularisation

Paramètres → Mise en service et pilote → Figer l’état de départ. C’est la référence du pilote : ce qui manquait le jour où l’on a commencé. Une fois des pièces déposées ou pointées, cette photographie ne peut plus être prise.
