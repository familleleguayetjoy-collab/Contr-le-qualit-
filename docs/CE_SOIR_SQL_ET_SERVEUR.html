ComplyEC — à faire ce soir

Base de données et serveur. Comptez environ 1 h 15. Faites les étapes dans l’ordre : chacune suppose la précédente.

Avant de commencer — deux choses à avoir sous la main :
  • l’accès à votre projet Supabase tnzdopummupchhupzcso (celui référencé dans supabase-config.js) ;
  • une adresse e-mail de test, différente de la vôtre, pour vérifier l’invitation d’un collaborateur.

1. Les trois migrations SQL ~15 min

Les trois fichiers sont dans le dossier supabase/ du dépôt. Je les ai exécutés sur une base Postgres 16 neuve : ils s’appliquent sans erreur et se rejouent sans erreur. L’ordre compte : le 002 s’appuie sur le 001, le 003 sur le 002.

1.1 — Ouvrir l’éditeur SQL

Dans Supabase : menu de gauche → SQL Editor → New query.

1.2 — Exécuter supabase/schema.sql

Ouvrez le fichier, copiez tout son contenu, collez dans l’éditeur, cliquez Run.

Crée : les tables cabinets et profiles, le type user_role, les fonctions user_cabinet_id() et is_ec_of_cabinet(), et les règles de sécurité (RLS).

Résultat attendu : « Success. No rows returned ». Des lignes NOTICE ... does not exist, skipping sont normales : ce sont les suppressions préventives.

1.3 — Exécuter supabase/schema_002_donnees_metier.sql

Même manœuvre, dans une nouvelle requête.

Crée : dossiers, anomalies, vigilance_analyses, bilans, formations_sessions, formations_participations, declarations_independance, procedures_versions, procedures_accuses, manuel_chapitres.

1.4 — Exécuter supabase/schema_003_lettres_et_vigilance.sql

Même manœuvre.

Crée : lettres_mission, lettres_mission_analyses, dependance_economique, beneficiaires_effectifs, formations_accueil, documents_generes, la vue registre_formation_conservation, et ajoute les colonnes de réglage du cabinet (seuils, rôles Tracfin) ainsi que les colonnes PPE et origine des fonds.

Corrige aussi un défaut du 002 : la catégorie d’anomalie ldm_non_actualisee manquait à la contrainte et aurait été refusée par Postgres.

1.5 — Vérifier que tout est là

Nouvelle requête, exécutez ceci :

select table_name
from information_schema.tables
where table_schema = 'public'
order by table_name;

Vous devez voir 18 lignes : anomalies, beneficiaires_effectifs, bilans, cabinets, declarations_independance, dependance_economique, documents_generes, dossiers, formations_accueil, formations_participations, formations_sessions, lettres_mission, lettres_mission_analyses, manuel_chapitres, procedures_accuses, procedures_versions, profiles, registre_formation_conservation.

S’il en manque une seule, ne passez pas à la suite : relancez la migration correspondante et notez le message d’erreur exact.

1.6 — Vérifier que la sécurité est active

select tablename, rowsecurity
from pg_tables
where schemaname = 'public'
order by tablename;

La colonne rowsecurity doit valoir true partout. Si une table est à false, ses données seraient visibles par n’importe quel cabinet : signalez-le-moi avant d’aller plus loin.

2. Le stockage des fichiers ~10 min

Les lettres de mission, notes et attestations générées doivent se ranger quelque part. Le schéma prévoit les colonnes (fichier_url, note_url, justificatif_url, logo_url) mais Supabase Storage se configure à la main.

2.1 — Créer le bucket

Menu de gauche → Storage → New bucket.

ChampValeur
Namedocuments
Public bucketNon — décoché
File size limit50 MB
Ne cochez pas « Public ». Un bucket public rend chaque lettre de mission accessible à toute personne connaissant l’adresse, sans authentification. Ce sont des documents couverts par le secret professionnel.

2.2 — Restreindre l’accès au cabinet

Retour dans SQL Editor, exécutez :

-- Chaque cabinet ne voit que ses propres fichiers : le premier segment du
-- chemin est l'identifiant du cabinet (ex. "<cabinet_id>/lettres/xxx.docx").
create policy "documents: lecture au sein du cabinet"
  on storage.objects for select
  using (
    bucket_id = 'documents'
    and (storage.foldername(name))[1] = public.user_cabinet_id()::text
  );

create policy "documents: depot au sein du cabinet"
  on storage.objects for insert
  with check (
    bucket_id = 'documents'
    and (storage.foldername(name))[1] = public.user_cabinet_id()::text
  );

Résultat attendu : « Success. No rows returned ».

3. La fonction d’invitation des collaborateurs ~20 min

Le fichier supabase/functions/invite-collaborateur/index.ts tourne côté serveur avec la clé « service role ». C’est lui qui crée le compte d’un collaborateur et lui envoie son e-mail de connexion. Sans lui, le bouton « Inviter un collaborateur » ne fait rien.

3.1 — Installer l’outil en ligne de commande

Sur votre poste, dans un terminal :

npm install -g supabase
supabase --version

Si npm n’est pas installé, prenez Node.js sur nodejs.org (version LTS) puis recommencez.

3.2 — Se connecter et rattacher le projet

supabase login
cd <dossier du dépôt ComplyEC>
supabase link --project-ref tnzdopummupchhupzcso

supabase login ouvre votre navigateur pour l’autorisation. link demandera le mot de passe de la base : c’est celui choisi à la création du projet (Settings → Database si vous l’avez oublié, vous pouvez le réinitialiser).

3.3 — Déployer

supabase functions deploy invite-collaborateur

Résultat attendu : « Deployed Function invite-collaborateur ».

3.4 — Indiquer l’adresse de l’application

Pour que le lien reçu par e-mail ramène vers ComplyEC et non vers une page vide :

supabase secrets set APP_URL=https://votre-domaine-complyec

Si l’application n’est pas encore en ligne, mettez temporairement l’adresse locale que vous utilisez, et refaites cette commande le jour du déploiement.

Rien d’autre à configurer : SUPABASE_URL et SUPABASE_SERVICE_ROLE_KEY sont fournis automatiquement par l’environnement des fonctions.

4. Vérifier que la création de compte fonctionne ~15 min

C’est le point que je n’ai jamais pu tester : le réseau de mon environnement bloque supabase.co.

4.1 — Autoriser les inscriptions

Supabase → Authentication → Providers → Email : « Enable Email provider » doit être actif.

Dans Authentication → URL Configuration, renseignez Site URL avec la même adresse que APP_URL.

4.2 — Créer un compte depuis l’application

Ouvrez ComplyEC, créez un compte avec votre adresse, et allez au bout de l’écran « Dernière étape » qui demande le nom du cabinet.

4.3 — Vérifier en base

select c.nom as cabinet, p.prenom, p.nom, p.role, p.email
from public.profiles p
join public.cabinets c on c.id = p.cabinet_id;

Vous devez voir une ligne, avec role = expert_comptable.

Si la requête ne renvoie rien, c’est le point le plus important à me remonter : notez le message d’erreur affiché dans l’application au moment de la validation, et faites une capture de la console du navigateur (touche F12, onglet « Console »).

4.4 — Inviter un collaborateur de test

Dans ComplyEC : Mon équipe → Inviter un collaborateur, avec votre adresse de test.

Vérifiez que l’e-mail arrive, puis :

select prenom, nom, role, email from public.profiles order by created_at;

Vous devez voir deux lignes, la seconde avec role = collaborateur.

Supabase limite l’envoi d’e-mails à quelques messages par heure tant qu’aucun serveur SMTP n’est configuré. Si l’e-mail n’arrive pas, regardez d’abord Authentication → Logs avant de conclure à une panne.

5. Renseigner votre cabinet ~10 min

Une fois votre compte créé, ces réglages remplacent les valeurs de démonstration. Remplacez les valeurs entre guillemets par les vôtres.

update public.cabinets set
  nom        = 'Alpes Expertise Comptable',
  adresse    = '...',
  telephone  = '...',
  -- Aucun texte ne chiffre ces trois seuils : ce sont vos règles.
  seuil_dependance      = 10,   -- % du chiffre d'affaires
  ldm_revision_mois     = 12,   -- ancienneté maximale d'une lettre de mission
  sessions_lbcft_par_an = 2,
  -- Article R. 561-23 du code monétaire et financier : deux rôles distincts.
  declarant_tracfin          = 'Prénom Nom',
  correspondant_tracfin      = 'Prénom Nom',
  tracfin_declare_au_service = false;  -- passez à true une fois déclaré
Pensez-y hors informatique : l’article R. 561-23 impose de communiquer l’identité du déclarant et du correspondant à Tracfin et au Conseil de l’Ordre. Les désigner dans le logiciel ne suffit pas. Une fois la déclaration faite, repassez tracfin_declare_au_service à true.

6. Pour plus tard — la rédaction assistée à ne pas faire ce soir

Ne mettez jamais de clé d’API Anthropic dans l’application. Tout ce qui part dans le navigateur est lisible par n’importe quel utilisateur en trois clics : la clé serait récupérée et facturée sur votre compte. C’est vrai de toute clé d’API, sans exception.

La bonne méthode est une Edge Function, comme invite-collaborateur : la clé reste sur le serveur, l’application lui parle sans jamais la voir. Quand vous voudrez le faire :

  1. créez la clé sur console.anthropic.com ;
  2. supabase secrets set ANTHROPIC_API_KEY=sk-ant-... ;
  3. dites-le-moi : j’écris la fonction serveur et je remplace redigerSyntheseVigilance par un appel à celle-ci.

En attendant, la synthèse de l’analyse de vigilance est rédigée dans le navigateur à partir de vos seules saisies. Elle fonctionne, hors ligne, sans clé.

Je bascule alors DB_MODE de demo à supabase dans db.js et je branche les écrans sur vos vraies données. Toute la couche d’accès est déjà écrite et vérifiée en mode démonstration ; il reste à l’éprouver contre la vraie base, ce que je n’ai pas pu faire d’ici.
